Get Started

Welcome to Canopy, your team's shared memory. It holds the team's docs, decisions, roadmap, tickets, and a running feed of everything people and their coding agents have done, with one golden rule: agents only ever stage changes; a human confirms the ones that matter.

Workspace

My Work

Your personal dashboard: To-Do, Previous activity, and now Tickets assigned to me.

Tickets

One queue for the whole org. Anyone submits a ticket (bug, request, question, access); anyone can take one. Statuses move Submitted → In progress → Done, or Declined. A ticket can link to a GitHub issue or PR, but never is one.

Roadmap & Feed

Roadmap is the admin-authored plan with milestone progress; Feed is the running timeline of everything that shipped.

Knowledge

Docs & Search

The versioned Docs library (Technical / Product), and full-text Search across everything, every result tagged live or staged.

Triage

Review & Maintenance

Review is the verdict queue for staged proposals and drafted decisions; Maintenance is occasional housekeeping — empty is the normal state.

Connect your agent

Mint a token under Settings → MCP access tokens, then install the Canopy plugin in Claude Code:

/plugin marketplace add SaplingLearn/canopy
/plugin install canopy@canopy

Changelog — judgment calls

Where the brief left room, here's what was decided and why.
01Tickets is one shared surface for the whole org — no separate requester shell. Anyone submits from the header button; anyone can be assigned. Everyone sees the same screens.
02Tickets sits at the end of Workspace, after Feed; the icon is drawn in the sidebar family (18px, 1.8 stroke, no fill). The green badge counts unassigned active tickets.
03Filters collapsed into one Open / Closed / All segment plus two selects — the status vocabulary is fixed, so per-status chips were noise.
04Two views: Table for scanning, Board grouped by status for working the queue. The toggle uses the Roadmap tab idiom in the header.
05Status pills are tinted: Submitted blue, In progress green, Done muted, Declined red. Priority chips are monochrome.
06"Needs attention" (unassigned + Submitted) is a 2px inset left rule plus a faint fill — the selected-card idiom, not a new color.
07Assignment from the picker is immediate — reversible, so no confirm step. Legal status moves only: Submitted → Start/Decline; In progress → Done/Back.
08The GitHub link field shows only until a link exists; after that, the plain "Linked to engineering work" line.
09My Work gains a third block, "Tickets assigned to me", with the To-do card treatment; Settings gains one "Ticket queue" cadence row.
